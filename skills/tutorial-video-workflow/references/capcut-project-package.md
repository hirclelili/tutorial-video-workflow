# 可编辑剪映工程包

## 交付定义

交付一个可整体复制到剪映草稿位置、打开后仍可人工精剪的工程目录。用户不应逐个拖入素材，也不应重新匹配画面和口播。

工程包至少包含目标剪映版本要求的草稿文件、工程内媒体资源、统一时间线清单和验证报告。具体草稿文件名与资源目录结构以用户当前剪映版本创建的原生空白工程为准，不硬编码某个历史版本。

## 生成流程

1. 检测剪映/CapCut 版本和草稿根目录，只读列出候选工程。
2. 要求用户选择一个由当前版本新建、可以正常打开的空白工程。复制它作为版本模板，绝不修改原工程。
3. 使用 Whisper 和 FFmpeg 生成已确认的分段素材；每段保留稳定 ID、源入出点、时间线位置、速度和音量。
4. 将所有正式引用的媒体复制到工程包内部的资源目录。复杂 Remotion 动效保持为独立 MP4，字幕保持原生可编辑文本。
5. 由 Python 将统一时间线转换为 CapCut Mate 输入，调用 CapCut Mate 在模板副本内生成或更新轨道、片段、字幕、位置、缩放和音量。
6. 把草稿中的媒体引用重写为包内实际路径；不得引用临时目录、缓存目录或原素材绝对路径。
7. 生成与工程时间线一致的低码率审片 MP4，运行结构检查，再让用户实际打开验证。

若缺少 CapCut Mate、其接口不支持目标版本，或没有可验证的原生模板，停止在“工程包尚未兼容验证”的状态。可以同时交付审片视频、统一时间线和处理后的独立素材作为恢复材料，但不得把它们称为完成的剪映工程包。

## 包内要求

- 一包即一个项目，不在包内放多个候选成片。
- 音画已经对齐，所有片段已放到正确时间线位置。
- 原生视频、音频、录屏、画中画和字幕尽量分轨。
- 预处理片段可继续裁剪；烘焙动效作为独立素材，可删除或替换。
- 工程元数据记录模板来源版本、CapCut Mate 版本、生成时间和已知限制。
- 原素材保持只读；包内媒体是交付副本。

## 验证顺序

1. 结构检查：草稿文件存在、JSON 可解析（若该版本使用 JSON）、轨道和素材引用完整、引用路径全部存在且位于工程包内。
2. 审片检查：代理视频的顺序、时长、同步、字幕和画面匹配符合已批准方案。
3. 剪映实机检查：工程出现在列表并可打开，无丢失素材，字幕可改，分轨合理。
4. 重开检查：在剪映中保存、关闭并重新打开后仍正常。

只有四项均通过才写入 `verified`。任何自动检查都不能替代第 3、4 项。
