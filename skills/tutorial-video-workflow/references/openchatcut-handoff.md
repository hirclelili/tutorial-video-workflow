# OpenChatCut 交接

## 角色

把 OpenChatCut 用作 Codex 粗剪后的可视化精剪工作台，不把它当作剪映保底工程的替代品。

## 前置条件

在交接前确认：

1. 剪映 V1 已生成；
2. 静态验证已通过；
3. 用户知道仍需在剪映中实际打开验证；
4. OpenChatCut 项目使用与剪映 V1 相同的绝对素材来源；
5. 剪映 V1 已备份且不会被覆盖。

## MCP 编辑

连接本机 OpenChatCut MCP 后：

1. 开始隔离编辑会话；
2. 默认使用手动审批模式；
3. 读取当前项目和轨道后再提出修改；
4. 把一组相关修改作为单次可撤销提案提交；
5. 等待用户在 OpenChatCut 中预览并批准；
6. 仅记录实际批准的操作。

不要假设 OpenChatCut 能直接导出剪映草稿。先检测可用导出能力。

## 修改日志

`openchatcut_changes.json` 中的每项操作至少包含：

- 操作 ID 和批准时间；
- 目标轨道和片段稳定 ID；
- 操作类型；
- 修改前值和修改后值；
- 输出时间码；
- 是否可自动映射回剪映；
- 无法映射时的人工操作说明。

优先记录结构化操作，不要只保存自然语言摘要。

## 回写降级策略

按以下优先级处理：

1. 直接转换 OpenChatCut 项目为新剪映版本；
2. 把结构化操作重放到原统一剪辑配置后重新导出；
3. 生成带时间码的剪映人工修改清单。

任何降级都不得删除或覆盖已验证的剪映 V1。
