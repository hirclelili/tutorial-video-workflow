# 依赖启动规则

## 原则

先检查，后解释，再申请许可，最后安装和验证。不要因为用户不会安装开发工具而把命令直接丢给用户；在取得许可后由 Codex 执行安全、受支持的安装流程。

## Python 缺失

Python 3 是基础依赖，因为项目初始化、剪映草稿验证、转写和 `video-editing` 脚本需要它。

1. 使用当前系统的原生命令确认缺失，不调用任何 Python 脚本。
2. 检测操作系统、CPU 架构和已有软件包管理器。
3. 向用户说明将安装 Python 3、安装来源和磁盘影响，并申请许可。
4. 优先使用已经存在且受系统支持的软件包管理器：
   - macOS：已有 Homebrew 时使用 Homebrew；否则采用 Python 官方安装方式或先单独征得安装 Homebrew 的许可。
   - Windows：优先使用可用的 Windows Package Manager；选择当前受支持的稳定 Python 3 包，不硬编码过期版本。
   - Linux：使用系统自带包管理器安装 Python 3 和虚拟环境支持。
5. 安装后运行版本检查，要求 Python 3，并重新执行 `bootstrap.sh` 或 Windows 原生检查。
6. 若安装失败，保留原任务状态并报告具体失败点，不假装环境已经可用。

## Python 包

不要把 Whisper 等项目包全局安装到系统 Python。优先在视频项目内创建 `.venv`，再安装当前任务真正需要的包。模型下载可能耗时和占用大量空间，必须在下载前说明。

## FFmpeg

Python 可用后检查 `ffmpeg` 和 `ffprobe`。两者通常由同一个 FFmpeg 安装提供。缺失时把它们作为一个基础依赖请求许可并安装，随后分别运行版本检查。

## 可选依赖

只在功能触发时处理：

- Node.js、Remotion、Chrome/Chromium：复杂动效；
- 用户已有的浏览器：打开内置粗剪与逐字精剪工作台；不要求 Chromium；
- OpenChatCut：仅供用户主动选择的高级外部精剪；
- CapCut Mate：生成或更新可编辑剪映工程结构；仅在用户要求剪映工程包时需要。优先使用其官方支持的安装方式并记录版本，不把未知来源脚本当作同名工具；
- 额外生成服务：封面、补充画面或音频生成。

可选依赖缺失不得阻塞内容清理、粗剪和审片代理，但缺少可用的 CapCut Mate 时不得宣称已完成可编辑剪映工程包。
